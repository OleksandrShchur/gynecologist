# Оксана Перхулин — акушер-гінеколог

Односторінковий інформаційний сайт українською мовою. React 18, TypeScript у strict mode, Vite, Tailwind CSS, `motion/react`, React Three Fiber 8, Shader Gradient та Liquid Glass. Сайт статичний: без форм, запису на прийом, серверної частини, аналітики й трекерів.

## Локальний запуск

Потрібні Node.js **22.12 або новіший** та npm.

```sh
npm install
npm run dev
```

Vite покаже локальну адресу в терміналі. Для відтворюваного встановлення з наявним `package-lock.json` можна використовувати `npm ci`.

```sh
npm run check    # TypeScript
npm run build    # перевірка типів, production-збірка та статичний HTML
npm run preview  # локальний перегляд dist/
```

`npm run images` автоматично виконується перед `dev` і `build`. Після зміни контенту чи фотографій потрібно повторити збірку перед публікацією.

## Контент і фотографії

Увесь текст інтерфейсу та відомості про лікаря зберігаються в типізованому [`src/content/site.ts`](src/content/site.ts). Необов’язкові дані з позначками `// TODO` можна залишати порожніми: їхні блоки не відображаються. Не додавайте непідтверджених кваліфікацій, відгуків, чисел або контактів.

Обидві надані фотографії збережено в проєкті:

- `src/assets/photo-portrait.png` — портрет за столом у лавандовому медичному одязі, рослина праворуч.
- `src/assets/photo-standing.png` — фото стоячи зі схрещеними руками у світлому кабінеті.

Портрет за столом показано в першому екрані, фото стоячи — у розділі «Про лікаря». На широкому екрані портрет розташований праворуч від тексту, на телефоні — перед ним. Портрет завантажується одразу з високим пріоритетом, фото нижче сторінкою — відкладено. Обидва використовують локальні адаптивні WebP, змістовний alt-текст і зарезервовані розміри.

Після заміни фото виконайте `npm run images` або перезапустіть `npm run dev`. Скрипт створює WebP до 480, 768 і 1120 px завширшки, зберігає пропорції та враховує EXIF-орієнтацію. Оригінали не збільшуються: для поточних фото найбільші версії мають 1080 px і 1092 px відповідно. `srcSet`, `sizes` і фактичні розміри допомагають завантажувати відповідне зображення та резервувати його місце. Згенеровані файли не потрібно редагувати вручну.

Докладніше про файли та автоматичну підготовку: [`src/assets/README.md`](src/assets/README.md).

Instagram має два посилання: у першому екрані та одну скляну картку в контактах. Контактний розділ поєднує короткий вступ і картку з назвою каналу, читабельним профілем та підписом дії; вся картка є посиланням. На телефоні вступ і картка розташовані один під одним. Кнопка «Контакти» в шапці веде до цього розділу. Закріпленої кнопки немає. Зовнішні посилання відкривають нову вкладку з доступним попередженням; внутрішні залишають відвідувача на сайті.

Шапка залишається компактною й має один рядок. На екранах вужчих за 1024 px розділи відкриваються в нативному меню `details` / `summary`; на широких екранах посилання показані безпосередньо. Поточний розділ позначається через `aria-current`, клавіша Escape закриває відкрите меню й повертає фокус до перемикача. Футер повторює палітру й типографіку сторінки: ім’я лікаря, короткі відомості та доступне посилання нагору.

## Що ще потрібно надати або погодити

- Біографію та освіту; за бажанням — підтверджений стаж.
- Місто, адресу клініки та телефон, якщо їх потрібно публікувати.
- Остаточну адресу сайту для canonical та Open Graph URL.
- Зображення для Open Graph, якщо потрібне власне прев’ю посилання.
- Погодження лікарем шести коротких описів напрямів, позначених `DRAFT_REVIEW` у `src/content/site.ts`.

Поки біографія й освіта порожні, розділ «Про лікаря» використовує тільки відоме ім’я, спеціальність та напрями. Телефон і адреса не показуються до заповнення. Відсутні URL сайту та Open Graph-зображення не замінюються вигаданими адресами.

## Градієнт і скляні поверхні

Перший екран має градієнт на всю ширину, справжній портрет лікаря, гасло, один підзаголовок та одну кнопку Instagram. Від 640 px текст розташований ліворуч, портрет на округленій прямокутній підкладці — праворуч. На вузьких телефонах портрет, гасло й кнопка утворюють компактну центровану композицію. Висота визначається вмістом, щоб на планшетах не виникало порожнього простору й кнопка залишалася видимою. Декоративну квітку прибрано. Тема сторінки залишається світлою; сливові, лавандові, рожеві та шавлієві відтінки пов’язують перший екран із наступними розділами.

[`PageBackground.tsx`](src/components/PageBackground.tsx) створює один фіксований градієнт за всією сторінкою: від шапки до контактів і футера. На телефонах і сенсорних планшетах кольори плавно рухаються через CSS `transform` із циклом 28 s. На настільних пристроях із точним вказівником окремий модуль [`HeroGradient.tsx`](src/components/HeroGradient.tsx) завантажує єдину WebGL-сцену з `ShaderGradientCanvas` і `ShaderGradient` через React Three Fiber; щільність пікселів обмежена до 0,75. Обидва види руху призупиняються під час прокручування та в прихованій вкладці, потім відновлюються без заміни canvas. Із `prefers-reduced-motion`, `Save-Data` та без JavaScript залишається статичний градієнт. Світла вуаль зберігає читабельність тексту.

[`Glass.tsx`](src/components/Glass.tsx) підтримує 15 поверхонь: кнопки Instagram, «Контакти» й «На початок», шість напрямів, три принципи, контактну картку та дві фоторамки. Кнопки повторюють кольорову напівпрозору підкладку карток, світлу грань і м’яку об’ємну тінь; текст та іконки залишаються темно-сливовими при наведенні, фокусі й виборі. У спокої використовується легка CSS-підкладка без `backdrop-filter`; `liquid-glass-react` завантажується лише для поверхні під вказівником або з фокусом клавіатури. Рухомі контурні накладки вимкнені, постійна рамка не змінює розміру. Рефракція вимикається під час прокручування й відновлюється після зупинки. [`scroll-activity.ts`](src/scroll-activity.ts) використовує один пасивний обробник без оновлень React на кожному кадрі. На мобільних пристроях, із зменшенням руху та без JavaScript залишається CSS-поверхня. Фоторамки повторюють об’єм кнопок; фотографії залишаються чіткими над декоративним шаром скла.

Час шейдера зберігається окремо від внутрішнього годинника бібліотеки: прокручування призупиняє рендеринг, а продовження починається з тієї самої позиції без перезапуску чи стрибка вперед. CSS-анімація також зберігає свій об’єкт і поточний час. QA перевіряє безперервність через фактичне значення `uTime`, передане до WebGL, і час CSS-анімації.

Для порівняння прокручування виконайте `node scripts/scroll-profile.mjs current`; `--isolate` окремо перевіряє вплив рефракції та шейдера. Звіти інтервалів кадрів, довгих задач і Chrome traces зберігаються в `.qa/scroll/`. Результати залежать від пристрою та графічного прискорення.

Розділи мають компактні відступи 28–40 px, текст від 16 px та кольорові підкладки під картками чи фото. Вступи напрямів і підходу стоять над картками. Шість напрямів утворюють три колонки від 1024 px та дві від 540 px. На вузькому телефоні всі шість карток показують повний опис без розкриття чи приховування; компактні відступи 12 px зменшують висоту списку; три принципи підходу стоять поруч від 768 px. У розділі «Про лікаря» текст і фото розташовані поруч від 640 px, у «Контактах» — від 768 px. Фото в розділі «Про лікаря» обмежене шириною 300 px і має скляну рамку без рефракції самого зображення.

Невикористані вихідні файли квітки збережені в `src/assets/`, але не імпортуються в перший екран і не завантажуються сторінкою. Фотографії лікаря не генерувалися й не ретушувалися.

## Анімація під час прокручування

У `index.html` оголошено спільні ключові кадри та підключено модуль [`src/scroll-animations.ts`](src/scroll-animations.ts):

```css
@keyframes animationIn {
  from { opacity: 0.98; transform: translateY(20px); }
  to { opacity: 1; transform: translateY(0); }
}
```

Для нового блоку використовуйте статичну обгортку `div` або `li` з повними Tailwind-класами:

```tsx
<div className="animate-on-scroll [animation:animationIn_0.68s_cubic-bezier(0.22,1,0.36,1)_both] [animation-delay:50ms]">
  {children}
</div>
```

Один `IntersectionObserver` обслуговує всі такі блоки. Реєстрація відбувається в React `useEffect` після гідратації. Коли блок досягає порога, модуль додає `.animate`, запускає анімацію один раз і припиняє спостереження за ним. Стан проходить `pending` → `running` → `done`. Без JavaScript контент одразу видимий: за замовчуванням CSS-анімація вимкнена.

Поки анімація очікує, текст повністю непрозорий. Початкову прозорість `0.98` обрано для збереження AA-контрасту і під час появи; основний видимий ефект створює зсув на 20 px.

Тривалість — `0.68s`, спільна крива — `cubic-bezier(0.22,1,0.36,1)`. Затримку можна змінювати повним класом `[animation-delay:50ms]` або `[animation-delay:100ms]`; залишайте класи літеральними, щоб Tailwind включив їх у збірку. Поріг `threshold: 0.2` та `rootMargin: '0px 0px -10% 0px'` налаштовуються в модулі спостерігача. Поява й рух при наведенні використовують різні обгортки, тому їхні `transform` не перезаписують один одного.

`prefers-reduced-motion` одразу переводить блоки в кінцевий стан. Перехід фокусу всередину завершує їхню появу, щоб навігація клавіатурою залишалася передбачуваною. Рух при наведенні вмикається для точного вказівника. Поява тексту першого екрана використовує `motion/react`; спільні часові параметри зберігаються у [`src/motion.ts`](src/motion.ts).

## Перевірки

```sh
npm run build
npm run qa
```

Автоматизована перевірка використовує Playwright, axe та Lighthouse і сама запускає локальний перегляд збірки на порту 4173. Їй потрібен установлений Chrome, Chromium або Edge; якщо браузер не знайдено автоматично, задайте шлях до нього через `CHROME_PATH`. Скриншоти й звіти зберігаються у `.qa/`; ця папка не входить до Git. Для перевірки вже запущеного сайту можна задати `QA_BASE_URL`. Деталі: [`scripts/qa.mjs`](scripts/qa.mjs).

Lighthouse працює в настільному Chrome з емуляцією мобільного пристрою та обмеженням CPU. Ця перевірка оцінює завантаження й стабільність сторінки; вимірювання FPS на фізичному телефоні виконується окремо.

Перевірка охоплює шість розмірів екрана, клавіатурну навігацію, доступність, локальне завантаження ресурсів, роботу без JavaScript та зменшення руху. Окремі перевірки контролюють настільний WebGL-градієнт, обмеження кількості canvas, резервний CSS-фон і скляні поверхні. Актуальні результати конкретного запуску зберігаються у `.qa/summary.json`.

Перед публікацією перевірте сайт на телефоні, навігацію клавіатурою, Instagram-посилання та режим зменшення руху. Після зміни фотографій або анімацій повторіть перевірку швидкодії: її результат залежить від фінальних файлів і хостингу.

## Публікація

Готовий результат збірки — папка `dist/`. Серверна частина або змінні середовища не потрібні. Файли конфігурації Vercel та Netlify вже додано.

**GitHub Pages:** ручне розгортання налаштовано у [`.github/workflows/deploy-pages.yml`](.github/workflows/deploy-pages.yml).

1. Додайте workflow та зміни збірки до `master` (або іншої default-гілки репозиторію), щоб у GitHub з'явилася кнопка **Run workflow**. Feature-гілка для розгортання також має містити ці зміни.
2. У **Settings → Pages → Build and deployment → Source** виберіть **GitHub Actions**.
3. У **Settings → Environments → github-pages → Deployment branches and tags** дозвольте розгортання з `master` та потрібних feature-гілок. Обмеження лише default-гілкою блокуватиме feature-гілки.
4. Відкрийте **Actions → Deploy to GitHub Pages → Run workflow**, виберіть `master` або feature-гілку в полі **Branch** і запустіть workflow.

Workflow встановлює залежності через `npm ci` на Node.js 22 та запускає `npm run build`, включно з перевіркою TypeScript і prerender. Публікація `dist/` виконується лише після успішної збірки. Push і pull request не запускають розгортання. Додаткові secrets не потрібні: використовується вбудований `GITHUB_TOKEN`.

Усі вибрані гілки публікуються на **один сайт GitHub Pages**: успішне розгортання feature-гілки замінює поточну опубліковану версію. Одночасно виконується лише один workflow розгортання; поточний запуск не скасовується.

Workflow отримує базовий шлях від GitHub Pages і передає його як `VITE_BASE_PATH` під час збірки, тому ресурси та статичні зображення працюють і за адресою `/gynecologist/`, і в корені власного домену. Локально та на інших хостингах базовий шлях за замовчуванням — `/`.

Налаштування та ручний запуск описані в документації GitHub: [custom workflows для Pages](https://docs.github.com/en/pages/getting-started-with-github-pages/using-custom-workflows-with-github-pages), [ручний запуск workflow](https://docs.github.com/en/actions/how-tos/manage-workflow-runs/manually-run-a-workflow).

**Vercel:** імпортуйте репозиторій як Vite-проєкт, виберіть Node.js 22, команду збірки `npm run build` та вихідну папку `dist`. Налаштування також записані у [`vercel.json`](vercel.json).

**Netlify:** імпортуйте репозиторій; [`netlify.toml`](netlify.toml) задає Node.js 22, команду `npm run build` і публікацію `dist`. Для ручного завантаження спочатку зберіть проєкт локально та завантажте вміст `dist`.

Перед остаточною публікацією внесіть реальний URL сайту в `site.ts` і перебудуйте проєкт. Публікація на зовнішньому хостингу не виконувалася.

## Як влаштовано проєкт

- `src/content/site.ts` — єдине джерело текстів та відомостей.
- `src/components/SiteHeader.tsx` — компактна шапка, нативне мобільне меню та поточний розділ.
- `src/components/HeroSection.tsx` — текст першого екрана, скляна кнопка та справжній портрет.
- `src/components/HeroScene.tsx` — умови відкладеного завантаження градієнта та резервний CSS-фон.
- `src/components/HeroGradient.tsx` — єдина WebGL-сцена Shader Gradient та керування її рендерингом.
- `src/components/Glass.tsx` — Liquid Glass і резервні читабельні поверхні.
- `src/components/ApproachSection.tsx` — три принципи підходу в скляних картках.
- `src/components/AboutSection.tsx` — текст про лікаря та справжнє фото на окремій підкладці.
- `src/assets/` — оригінали фото та автоматично створені WebP.
- `scripts/optimize-images.mjs` — підготовка адаптивних зображень.
- `scripts/prerender.mjs` — статичний HTML, українські SEO-метадані та JSON-LD `Physician` під час збірки.
- [`DESIGN.md`](DESIGN.md) — палітра, шрифти та правила інтерфейсу.

HTML сторінки має `lang="uk"`. Контент і метадані доступні в зібраному HTML до виконання JavaScript; React додає інтерактивність. JSON-LD містить лише підтверджені дані, а необов’язкові поля додаються після заповнення. Шрифти Manrope та Cormorant Garamond із підтримкою української завантажуються локально через `@fontsource`.
